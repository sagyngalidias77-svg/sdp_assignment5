# Assignment 5 қорғауға дайындық

## Жобаның мақсаты

Бұл бағдарлама дайын 8 маршруттың ішінен жеткізуге қолайлы біреуін таңдайды. Бір тапсырысқа ең жылдам жол керек, екіншісіне ең арзан немесе экологиялық жол керек. Сондықтан әр таңдау алгоритмі жеке Strategy класына жазылған.

Бұл нұсқаулықты кодпен бірге оқып, мысалдарды өзің іске қосып көр. Қорғауда кодтың қалай жұмыс істейтінін және нәтижені неге таңдағанын түсіндіру керек.

## Қай файлды қандай ретпен оқу керек

1. `Route`, `Location`, `DeliveryRequest`, `DeliveryPriority`: қандай деректер сақталады.
2. `RouteStrategy`: барлық алгоритмдерге ортақ интерфейс.
3. `RoutePlanner`: алгоритмді сақтайды және соған жұмысты береді.
4. `RouteRules`: уақыт, толық баға және шектеулер.
5. `ScoredRouteStrategy`: жарамсыз маршруттарды алып тастау және ең кіші score таңдау циклі.
6. Бес нақты стратегия: әрқайсысының score формуласы.
7. `StrategySelector`: тапсырысқа қарай алгоритм таңдайтын Map.
8. `Main`: бағдарламаның көрсетілімі.
9. `RouteEngineTest`: күтілетін нәтижелерді тексеру.

`record` — өзгермейтін дерек сақтайтын қысқа Java класы. Мысалы, `route.distanceKm()` қашықтықты қайтарады. `interface` — кластар орындайтын келісім. `extends` ортақ кодты мұраға алады. `List` бірнеше элемент сақтайды, `Map` кілт бойынша мән табады.

## Strategy Pattern туралы қысқа жауап

«Context — RoutePlanner. Strategy интерфейсі — RouteStrategy. Нақты стратегиялар — Fastest, Cheapest, EcoFriendly, Balanced және DistanceFirst. RoutePlanner алгоритмнің ішкі формуласын білмейді. Ол selectRoute әдісін шақырады. setStrategy арқылы бір объектінің алгоритмін программа жұмыс істеп тұрған кезде ауыстырамын».

`RoutePlanner.plan()` әдісін ашып көрсет: онда тек делегация бар. `Main` басында Fastest → Cheapest → Eco → Balanced тізбегі көрсетілген. Бұл үш ауысу, төрт бөлек planner емес.

## Әр алгоритмді түсіндіру

**Fastest:** бастапқы уақытқа кептеліс минуттарын қосады. R1: 20 + 10 = 30 минут. R2: 22 + 2 = 24 минут. Бастапқы уақыты үлкен болса да, R2 жылдам болып шығады.

**Cheapest:** бастапқы баға + әр километрге 100 теңге + URGENT болса 500 теңге + қосымша төлем. STANDARD кезінде R3: 700 + 8 × 100 = 1500 теңге. Барлық стратегия бюджет тексергенде осы толық бағаны қолданады.

**Eco:** CO2 × 0.8 + қашықтық × 0.2. Бұл экологиялық салыстыру ұпайы, нақты CO2 мөлшері емес. Формула Eco стратегиясында орналасады, өйткені ол сол алгоритмнің таңдау ережесі.

**Balanced:** уақыт, баға, қашықтық және шығарындылардың өлшем бірліктері әртүрлі. Оларды 0–1 аралығына келтіреміз: `(мән − min) / (max − min)`. Кейін салмақтарға көбейтіп қосамыз. Салмақтар 0.4, 0.3, 0.1, 0.2; қосындысы 1. Егер max = min болса, нөл аламыз: бөлгіш нөл болмауы керек. Есепке тек жарамды маршруттар кіреді.

**DistanceFirst:** жарамды маршруттардың ең қысқасын таңдайды. R5 — 6 км. R7 — 5 км болғанымен, қолжетімсіз, сондықтан таңдалмайды.

## Шектеулер score есептеуден бұрын тексеріледі

Қолжетімсіз маршрут, бюджеттен асқан толық баға немесе дедлайннан асқан толық уақыт маршрутты жарамсыз етеді. Төмен score бұл шектеулерді жоймайды. Бюджетке не дедлайнға дәл тең болса, маршрут жарамды.

Барлық маршрут жарамсыз болса, `NoSuitableRouteException` тасталады. Оның ішінде себептер бар. `null` қайтарылмайды. Қате салмақ пен теріс мәндерге `IllegalArgumentException`, міндетті объект жоқ болса `NullPointerException` қолданылады.

## StrategySelector не үшін керек

Strategy маршруттарды қалай салыстыру керегін біледі. Selector қай стратегияны қолдану керегін шешеді. EnumMap ішінде URGENT → Fastest, ECONOMY → Cheapest, ECO → Eco, STANDARD → Balanced сәйкестігі бар.

`ecoPreferred = true` тек STANDARD таңдауды Eco-ға өзгертеді. URGENT тапсырыстың басымдығы сақталады. `register()` арқылы сәйкестікті ауыстыруға болады.

## Нәтиже неге өзгеруі мүмкін

STANDARD, бюджет 6000, дедлайн 60 кезінде Fastest R2 таңдайды. Бюджетті 3000-ға азайтсақ, R2 бағасы 5000 болғандықтан алынып тасталады. Сол Fastest алгоритмі енді R6 таңдайды: 32 минут, 2900 теңге. Демек нәтиже hardcoded емес.

## SOLID және Bridge

- SRP: Planner делегация жасайды, стратегия есептейді, Selector алгоритм таңдайды, Main нәтижені шығарады.
- OCP: DistanceFirst қосылғанда RoutePlanner өзгерген жоқ. Жаңа класс қосылып, Main-дегі тізімге тіркелді.
- DIP: RoutePlanner нақты Fastest класына емес, RouteStrategy интерфейсіне тәуелді.

Strategy бір операцияның алгоритмдерін ауыстырады. Bridge екі тәуелсіз өзгеретін иерархияны бөледі, мысалы хабарлама түрі мен оны жеткізу арнасы. Екеуі де composition қолдана алады, бірақ мақсаты бөлек. Өткен тапсырмаңдағы нақты Bridge кластарын өз кодыңмен байланыстырып түсіндір.

## Live modification жаттығулары

1. Main ішіндегі Balanced салмақтарын `(1, 0, 0, 0)` етіп өзгерт: стандартты сұраныста R2 күтіледі. `(0, 1, 0, 0)` болса R3 күтіледі. Кейін бастапқы мәнді қайтар.
2. Бюджетті 3000-ға түсіріп, Fastest нәтижесін тексер: R6.
3. Дедлайнды 20 минут ет: қолжетімді маршруттардан ешқайсысы өтпейді, exception болады. Main-ге try/catch қосып көрсет.
4. `selector.register(DeliveryPriority.STANDARD, new DistanceFirstStrategy())` жолын қос: STANDARD енді R5 таңдайды.
5. Жаңа стратегия үшін DistanceFirst үлгісін көшіріп, атауын және score формуласын өзгерт. Main тізіміне қос. Нақты күтілетін маршрутты тексеретін JUnit тест жаз.

## Тест пен Git көрсету

```bash
./mvnw clean test
./mvnw package
java -jar target/smart-delivery-1.0.0.jar
git log --oneline --reverse
git log --oneline --grep='Add fifth'
```

30 тесттің барлығы өтті. Әр тест тек объектінің бар екенін емес, дұрыс маршрут, формула, шектеу немесе exception нәтижесін тексереді. Fifth strategy commit-ін ашып, тек жаңа класс пен Main тіркеуі өзгергенін көрсет.

Git commit-тері осы жұмыс барысында нақты кезеңдермен жасалды. Тарихты бір апта бойы жасағандай көрсетуге немесе күндерін өзгертуге болмайды. Оқытушының даму тарихын бағалауы бөлек екенін ескер.
